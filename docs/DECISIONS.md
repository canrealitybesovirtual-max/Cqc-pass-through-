# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-11-27 | Build from scratch. CQC, Blackout and Scanner are references only. | The old scanner was glitchy and the old guns cost too many draw calls. Repeating their code would repeat their problems. |
| 2026-11-27 | The repository is `canrealitybesovirtual-max/Cqc-pass-through-` | The user's choice |
| 2026-11-27 | All CQC assets (models, sounds) are cleared for use | The user confirmed the licences |
| 2026-11-27 | three.js r187 with `WebGLRenderer` | PLAN §1: depth occlusion is built in. WebGPURenderer's XR has no depth sensing. |
| 2026-11-27 | Plain JavaScript with JSDoc + `@ts-check`, no build step | The user didn't choose, so this uses the plan's recommendation |
| 2026-11-27 | Holster default: right hip | The user didn't choose, so this uses the plan's default. It can be changed in settings (Phase 5). |
| 2026-11-27 | Pistol source shape: CQC M1911, re-baked into the 2-draw layout | Its parts are already split and it is now licensed. G17 stays an option. |
| 2026-11-27 | Hosting: a Render static site from `main` | The user tests on the headset only, so testing needs an HTTPS origin, and it must stay the same origin for anchors and rooms |
| 2026-11-27 | Play sessions use `local-floor` and never request `unbounded` (superseded in v0.3: Play is Roam) | The system boundary stays untouched during combat (PLAN §2) |
| 2026-11-27 | Depth sensing is off in play by default; probe sessions always request it | Its cost and side effects are measured in Phase 2 first (PLAN §5) |
| 2026-11-27 | three's depth texture is pointed at the current frame's texture before every render (`src/xr/LiveDepth.js`) | three r187 wraps the first frame's texture once. If the Quest hands out a texture per frame, the depth froze at session start and a hand never hid the cube (the user's report from the p1 probe session). A no-op when the browser reuses one texture |
| 2026-11-27 | three's depth quad gets `colorWrite = false` | Its shader writes only `gl_FragDepth`; the colour output was undefined over passthrough. Not part of the program key |
| 2026-11-27 | v0.2 play draws the guns in the main scene (no `fpScene` second pass) | Play has depth sensing off, so real hands cannot cut the gun. The second pass comes with the "Dynamic occlusion" setting |
| 2026-11-27 | In play every controller button belongs to the game; the Phase 1 probes (A timing, B rate, X clear, grips exit) stay in probe sessions. A 60 s timing run starts with wave 1 | A, B, the stick and both grips are weapon controls; hold Y (or the wrist menu) exits |
| 2026-11-27 | EnemyManager applies `enemyHit` from the event bus; WeaponSystem is built without `{ enemies }` | One place applies damage, so a hit is never applied twice |
| 2026-11-27 | The `reduced` retry (play with only `local-floor`) runs the game in a virtual room | It is play's fallback request; it has no Space Setup data |
| 2026-11-27 | v0.2.1: the round starts only after the safe-spot confirmation (`game.pickSpot`); a spot more than 0.25 m from where the world was built rebuilds it there, behind the "Get ready" panel | PLAN §6.2 / gap audit S1: a round could start with a wall inside the ring. The world's nav, spawns and zone belong to the chosen spot |
| 2026-11-27 | v0.2.1: the "Get ready" panel carries a controls card and stays up until a trigger pull (after 1 s) or 8 s | The capture takes about a second; the controls are not discoverable in the headset otherwise |
| 2026-11-27 | v0.2.1: play asks for 72 Hz at start | The AR default is 90 Hz (DEVICE_LOG p1.0); four procedurally animated enemies are unmeasured on the Quest, and 72 Hz gives 13.9 ms a frame |
| 2026-11-27 | v0.2.1: camera near plane 0.02 m in play without depth sensing | The AKM's stock sits 0.27 m behind the grip and clipped through the face at 0.05. Depth sessions keep three's depth-data near plane |
| 2026-11-27 | v0.2.1: Copy exports only the last session; Download / Share keep everything | Twelve sessions plus hitch logs were too large to paste into the chat |
| 2026-11-27 | v0.2.1: the grip fit escape hatch (`?gripPitch`, `?gripY`, `?gripZ`) is applied by PlayKit to the WeaponViews' palm point and `holdPose` | WeaponView's FIT is frozen and has no hook, and `src/weapons/` belongs to another builder. A proper fit setting belongs in WeaponView (Phase 5 calibration) |
| 2026-11-27 | v0.2.1: the card moves on when the trigger is released, not when it is pulled | The card's step runs before `game.preUpdate` in the same frame, so a trigger-down there also confirmed a clear or unmapped spot at once: the spot step was skipped (seen in a virtual room in the emulator) |
| 2026-11-27 | v0.3: Play is Roam (the whole house) and is the default Enter MR: it requests `unbounded` and uses it when granted, else `local-floor` with an honest note on the page and in the record (`spaceNote`: "the Quest boundary applies"); there is no fixed safe zone. The stationary v0.2 mode is the second button, Enter MR: one spot (`spot`, `local-floor` only). Supersedes "Play sessions use `local-floor` and never request `unbounded`" | The user's v0.2 test: the Quest boundary they can draw covers half their room, and they want to walk the whole house. A web page cannot hide the Guardian; whether it shows under `unbounded` in the browser is unverified |
| 2026-11-27 | v0.3: running is a watch warning (vibration + icon), not a pause | Realism first: walking briskly between rooms is normal play. Tracking loss, visibility, controllers, frame gaps, B + Y, the menu and resets still pause |
| 2026-11-27 | v0.3: no text in the view during play: Roam shows only pauses, round over and exiting; every walking cue is diegetic on the watch | The user: "no UI in your face during play" |
| 2026-11-27 | v0.3: the watch replaces the wrist HUD and the wrist X tap / hold; it is the only menu (touch the dial with the right controller or point + trigger). Its frame comes from the left target ray (the grip fallback uses IWER's grip → ray relation) | The v0.2 wrist panel read mirrored and upside down on the headset; the user asked for a well-designed watch menu |
| 2026-11-27 | v0.3: the watch's trigger belongs to the watch while the right hand points at it or its menu is open (`watch.capture`): no shot (`weapons.triggerBlocked`), no resume press, no card skip | One pull must never do two things |
| 2026-11-27 | v0.3: the watch's DIFFICULTY row sets the enemy preset (EnemyManager `test` / `realistic`: damage, aim, reaction); GameSession's own damage multiplier stays × 1 | Two multipliers on the same damage would scale it twice. The URL's `?difficulty=` wins over the saved choice |
| 2026-11-27 | v0.3: the watch's MODE row switches the current session's rules (the world is rebuilt in the other mode behind the card and the round starts over); it is not saved. The page's two buttons choose the mode at Enter | The reference space cannot change mid-session, and "Enter MR" must stay the whole house |
| 2026-11-27 | v0.3: guns are held in grip space (`GunFit`); the player's per-gun nudges (pitch, up, forward) are applied live from the watch's GUN FIT page and saved per weapon in `localStorage['cqcpt.gunfit.v1']` from a `setTimeout` (never from the frame loop). Precedence: URL > saved > default; URL values are never saved. The GUN FIT page holds the chosen gun in the right hand without the squeeze (`weapons.fitHold`) | The v0.2 screenshots: the Glock sat above the controller pointing up along the handle. The fit must be adjustable in the headset (the user has no PC) |
| 2026-11-27 | v0.3: CQC's face-button map on either hand that is on the gun (A / X magazine release, B / Y slide release or AKM fire mode); holding A 0.8 s with no magazine is the assisted reload (a second tap no longer reloads). Y and B + Y belong to the game only with free hands | The user asked for more of CQC's reload mappings |
| 2026-11-27 | v0.3: the AKM is hidden while slung; the holster shell is anchored by the Glock's grip centre; seated, the holster moves onto the right thigh. One seated decision (the BodyEstimator's) feeds the Player and GameSession | The v0.2 screenshots: the slung AKM and the holster looked wrong when looking down. Seated play must not trigger the walking rules |
| 2026-11-27 | v0.3: `scene.environment` is a PMREM room made in `createRenderer` before the warm-up and never replaced or nulled; enemy cloth `envMapIntensity` 0.35 | It is part of every standard material's program key; changing it later would recompile mid-play. Cloth looked shiny at 1 (CQC) |
| 2026-11-27 | v0.3: gloved hands come inside the gun GLBs and share the gun's shader hook (double-sided since the verifier pass: one more program, compiled in the warm-up); on by default, `?gloves=0` turns them off | The white controller showed round the gun; no upload after the warm-up |
| 2026-11-27 | v0.3: nothing is stored as an XRAnchor; a reference-space reset during the round (or drift of the Space Setup reference planes over 0.10 m / 2° twice in a row) realigns the world behind a held pause (enemies back in the queue, one warm draw), and a reset before the round captures again | Anchors are reported to fail under `unbounded` on Quest 3; the planes are the ground truth. v0.2 only paused on a reset and left the world in the old coordinates |
| 2026-11-27 | v0.3: interior wall slabs are centred on their plane in Roam; the nav grid is never cropped (coarser cells instead) | The player walks round both sides of every wall; a crop around the start breaks when the player walks out of it |
| 2026-11-27 | v0.3: the user's chosen extras (brainstorm items 10 automatic diagnostics upload, 8 home defense, 7 room clearing) are not in this build; only their data side exists (rooms, door graph, exterior doors) | The user picked only 10, 8 and 7 from the extras; this integration wired the v0.3 core |
| 2026-11-27 | v0.3 verifier: the glove material is double-sided (set in WeaponView at load, before the warm-up) | The CQC pack hands are open shells made to be seen from the side; from the shooter's eye the culled cuff and palm read as a thin black wing over the grip. One more program (24 at warm-up), nothing changes it later |
| 2026-11-27 | v0.3 verifier: GameSession shows no message panel while the watch menu is open (except "exiting") | The menu's own MANUAL pause put "Pull the trigger to resume" half behind the menu disc, asking for a pull the watch owns; the menu is the only UI |
| 2026-11-27 | v0.3 verifier: unit-test timing bounds count only time on the CPU (`tests/unit/cpuclock.js`: thread CPU time over loops, single calls only when the thread was not switched out); allocation checks take the best of up to 8 reps (early exit) | With `npm test` runs in parallel the wall-clock bounds failed (roam bake slices 2.6–3.8 ms, spawn calls 6–11 ms that were GC-helper waits) and V8's late re-optimisation boxed doubles for a rep or three. The code keeps its own wall-clock deadlines |
